## 二、各文件功能详解

### 1. [main.py](参赛代码/main.py) — 主控制程序（核心文件，2244行）

**功能概述：** 四足机器人的完整赛道自主导航控制程序。通过 LCM 协议与仿真/真实机器人通信，按照预编程的路径点序列，控制 CyberDog 机器人依次完成赛道上六个阶段的所有障碍物和任务。

#### 1.1 导入依赖（第1-29行）
- `lcm`：轻量级通信与编组协议，用于与机器人仿真器/控制器通信
- `toml`：解析 TOML 配置文件
- `numpy`：数值计算
- `threading`：多线程支持
- 自定义 LCM 消息类型：`simulator_lcmt`（仿真器状态）、`robot_control_response_lcmt`（机器人控制响应）、`robot_control_cmd_lcmt`（机器人控制命令）

#### 1.2 核心类与函数

| 名称 | 位置 | 功能说明 |
|------|------|---------|
| `robot_cmd` (字典) | 第31-41行 | 机器人控制命令的默认参数模板，包含模式(mode)、步态ID(gait_id)、速度(vel_des)、姿态(rpy_des)、位置(pos_des)等 |
| `Pos_msg` 类 | 第43-68行 | LCM 位置消息接收器。订阅 UDP 多播地址 `239.255.76.67:7667` 上的 `simulator_state` 频道，实时获取机器人的三维位置(position[x,y,z])、欧拉角(rpy)、四元数姿态(quat)。包含角度归一化处理逻辑 |
| `Gait_msg` 类 | 第70-86行 | LCM 步态消息接收器。订阅 `239.255.76.67:7670` 上的 `robot_control_response` 频道，获取当前步态ID和模式 |
| `generate_waypoints()` 函数 | 第89-552行 | **路径规划核心函数**。生成约569个三维路径点(x, y, yaw)，覆盖整个赛道的6个阶段。通过分段线性/平滑插值方式定义从起点到终点的完整轨迹 |
| `eval_velocity()` 函数 | 第554-596行 | **PID 控制器**。根据当前位置与目标路径点的偏差，计算 x/y 线速度和偏航角速度。使用 P 控制(比例系数 Kp=1.55)计算前进速度，PI+D 控制(Kp=1.00, Ki=0.01, Kd=0.001)计算转向速度。判断是否到达路标点(距离<0.10m 且角度偏差<0.17rad) |
| `get_yaw_from_quaternion()` 函数 | 第598-606行 | 四元数转偏航角（yaw）的数学转换 |
| `Robot_Ctrl` 类 | 第608-643行 | **机器人控制发布器**。以 5Hz 频率(0.2s间隔)通过 LCM 向 `239.255.76.67:7671` 发布 `robot_control_cmd` 控制命令 |

#### 1.3 主函数 `main()` 执行流程（第645-2242行）

主函数按照赛道的六个阶段依次执行，每个阶段由"路径点导航 + 跳跃/站立切换"组成：

##### 阶段一（第1赛段）：起点 → 第1转弯点
- **waypoints 索引 0-9**：沿 x 轴从 (0,0) 前进到 (3,0)，yaw=-3.1
- 初始状态：mode=12(站立), gait_id=10, 站立高度0.28m
- 跳跃序列：跳1(gait_id=3, 右跳) → 立0 → 跳1 → 立1 → 走1(gait_id=27, 慢走)
- 使用 PID 控制导航

##### 阶段一弯道过渡（第1-2赛段间）
- **waypoints 10-18**：包含左转、右跳、左跳等跳跃动作切换
- 特殊步态使用：gait_id=80（匍匐/降低身高过限高杆，pos_des z=-0.1, step_height=0.005）

##### 阶段二（第2赛段）：过弯道 → 限高杆
- **waypoints 19-103**：复杂的 S 型弯道路径，包含多处跳跃
- **waypoints 104-126**：沿弯道前进到限高杆区域
- **waypoints 127-130**：使用 gait_id=80 匍匐通过限高杆（降低身高10cm，极小步高0.005m）
- **waypoints 131-140**：返程过限高杆

##### 阶段三（第3赛段）：前往篮球区域
- **waypoints 141-156**：从限高杆返回并导航到篮球区域
- **waypoints 157-174**：前往篮球（前跳+右跳组合）
- **waypoints 175-192**：从篮球返回
- 篮球区域使用了特殊的站姿切换和跳跃(gait_id=3, 右跳 duration=2000ms)

##### 阶段四（第4赛段）：前往可乐瓶赛道 → 撞可乐瓶
- **waypoints 193-202**：从篮球区导航到可乐瓶赛道
- **waypoints 203-215**：前进到限高杆前
- **waypoints 216-223**：使用 gait_id=80 过限高杆
- **waypoints 224-238**：撞可乐瓶（目标位置 y 从 9.875 到 11.113）
- **waypoints 239-266**：返回限高杆（原路返回 + 再穿限高杆）

##### 阶段五（第5赛段）：五条赛道快速穿越
- **waypoints 282-302**：准备进入第5阶段，x从0.0到3.04转向
- **waypoints 303-332**（第1条道）：沿 y 轴从 8.032 直走到 12.352，28个点
- **waypoints 333-352**（第2条道）：x 从 3.139 到 -0.449，y 从 12.353 到 12.407，20个点
- **waypoints 353-392**（第3条道）：沿 x=-0.38 线从 y=12.473 到 15.163，30个点
- **waypoints 393-412**（第4条道）：x 从 -0.284 到 3.188，19个点
- **waypoints 413-428**（第5条道）：定点转向，最终右跳

##### 阶段六（第6赛段）：最后冲刺 → 终点
- **waypoints 429-569**：最后的长距离穿越，包含多处平滑轨迹
- 最终使用 mode=7（PureDamper 纯阻尼模式）平稳停止，匍匐结束

#### 1.4 控制模式(mode)说明

| mode | 含义 | 用途 |
|------|------|------|
| 7 | PureDamper（纯阻尼模式） | 停车/安全停止/匍匐 |
| 11 | 运动模式 | 正常行走导航 |
| 12 | 站立模式 | 步态转换中间状态/等待 |
| 16 | 跳跃模式 | 跨越障碍物 |
| 62 | 自定义步态模式 | 特殊步态(moonwalk等) |

#### 1.5 关键步态ID(gait_id)说明

| gait_id | 含义 |
|---------|------|
| 0 | 站立/停止 |
| 1 | 前跳 |
| 2 | 快速前进 |
| 3 | 右跳(旋转跳跃) |
| 10 | PID导航步态/后退 |
| 27 | 小跑步态(慢速行走/转弯) |
| 80 | 匍匐步态(过限高杆专用) |
| 110 | 自定义步态(moonwalk风格) |

### 3. [usergait_def.toml](参赛代码/toml/usergait_def.toml) — 自定义步态足端接触序列定义

**功能概述：** 定义四足机器人每条腿在不同时间段内的着地/离地状态(contact sequence)。这是"Moonwalk"风格步态的低层足端轨迹定义。

- `contact = [FR, FL, RR, RL]`：四条腿的着地状态（1=着地，0=离地）
- 每个 `[[section]]` 定义一个时间段，`duration` 为该段持续的周期数
- 共定义 **4 个完整步态周期**，每个周期包含：
  - 四足支撑期 (contact=[1,1,1,1], duration=3)
  - 依次抬起 FR/RL/RR/FL 单腿 (contact 中对应腿为0, duration=6)

---

### 4. [usergait_param.toml](参赛代码/toml/usergait_param.toml) — 自定义步态运动学参数

**功能概述：** 为 Moonwalk 步态提供详细的运动学参数（使用 `usergait` 类型），共16个step。

**关键参数：**
- `body_vel_des = [0.1, 0, 0]`：期望身体前进速度 0.1 m/s
- `landing_pos_des`：四条腿的落足点位置（12个值，每腿3个坐标）
  - 每步有一条腿前移 0.065m，其他腿保持原地
- `step_height = [0.13, 0.13, 0.13, 0.13]`：步高 13cm
- `weight = [10, 10, 10, 50, 50, 10]`：MPC 权重（姿态权重高）
- `mu = 0.4`：摩擦系数
- `landing_gain = 1.0`：着陆增益系数
- `gait_id = 110`：步态ID
- `duration = 270`：每一步持续时间 270ms

---

### 5. [usergait_param_full.toml](参赛代码/toml/usergait_param_full.toml) — 自定义步态完整参数

**功能概述：** `usergait_param.toml` 的完整版本，以 `mode/gait_id` 格式（而非 `type/usergait`）定义步态参数。包含相同的16个step但参数格式更完整。

**关键差异：**
- 使用 `mode=11, gait_id=110` 格式
- `acc_des` 使用 `[10,10,10,50,50,10]` 权重数组（而非 `weight` 字段）
- `ctrl_point = [0, 0, 0.4]`：控制点位置
- `step_height` 使用 `[130130, 130130]` 编码格式

---

### 6. [Gait_Def_height.toml](参赛代码/Gait_Def_height.toml) — 限高杆步态定义

**功能概述：** 专门为"限高杆"障碍设计的步态足端接触序列。共30个section，交替切换对角线支撑：
- `contact = [1,0,1,0]`（FR+RR着地，FL+RL抬起）和 `[0,1,0,1]`（FL+RL着地，FR+RR抬起）
- 每个section duration=5，实现快速交替的匍匐爬行

---

### 7. [Gait_Params_height.toml](参赛代码/Gait_Params_height.toml) — 限高杆步态参数

**功能概述：** 为限高杆匍匐步态(gait_id=110)提供运动学参数，共14个step。与正常步态参数相比：
- `body_vel_des = [0, 0, 0]`：原地不动
- `landing_pos_des` 固定为 `[0.1, 0.1, 0.1, ...]`
- `step_height = [0.03, 0.03, 0.03, 0.03]`：步高仅3cm（极低）
- `duration = 150~300ms`

---

### 8. [Gait_Params_height_full.toml](参赛代码/Gait_Params_height_full.toml) — 限高杆步态完整参数

**功能概述：** `Gait_Params_height.toml` 的完整版本，14个step。差异：
- 使用 `mode=11, gait_id=110` 格式
- `step_height = [30030, 30030]` 编码格式（代表3cm）

## 五、技术要点总结

1. **通信协议**：基于 LCM (Lightweight Communications and Marshalling) 的 UDP 多播通信，三个频道分工明确（状态接收7667、步态响应7670、命令发送7671）

2. **控制策略**：预编程路径点 + 在线 PID 闭环控制，实现"全局规划+局部纠偏"的导航策略

3. **步态设计**：通过 TOML 配置文件定义多种步态，包括：正常行走、小跑、匍匐、跳跃（左跳/右跳/前跳）、Moonwalk 自定义步态等，针对不同障碍物使用不同步态

4. **特殊障碍应对**：
   - **限高杆**：使用 gait_id=80 匍匐步态，降低身高10cm，步高仅0.5cm
   - **弯道**：预生成平滑路径点配合 PID 控制
   - **跳跃**：mode=16 + gait_id=0(左跳)/1(前跳)/3(右跳) 组合

5. **安全机制**：每段路径后复位为站立模式(mode=12)，最终以 mode=7(PureDamper) 安全停止，`KeyboardInterrupt` 异常处理确保紧急停止
