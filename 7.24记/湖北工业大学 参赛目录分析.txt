1. 文档
README.md
项目说明文档。描述工程结构（cyberdog_demo、cyberdog_interfaces、cyberdog_test、launch、docs），环境要求（ROS 2 Galactic、Python 3、OpenCV、LCM），构建和运行方式，以及分支/提交规范。

cyberdog_demo_technical_document.md
技术文档，详述系统架构、五关策略（跳跃→撞球→PID寻线→低姿通过→跳跃），节点与话题设计、LCM 运动控制接口、视觉处理算法、PID 控制参数和已知问题。

2. 主控节点
master.py — 比赛主控节点
核心文件，包含三个重要类：

类	                     作用
PIDController	带积分限幅抗饱和的 PID 控制器（Kp=0.00170, Ki=0.00003, Kd=0.00010），输出限幅 ±0.30 rad/s
PIDTelemetry	PID 遥测可视化窗口（OpenCV），实时显示 gap、vyaw、vy 及 P/I/D 分解曲线，支持 200 帧历史
Robot_Ctrl_Node	LCM 通信封装，通过 UDP 组播发送 robot_control_cmd 和接收 robot_control_response，维持 10Hz 心跳
masterNode      订阅 6 个视觉话题（adjust_topic、ground_topic、seek_001_topic、fish_rgap_topic、hit_ratio_topic、fish_line_topic），实现五关动作序列：
第一关：mode=11 前进后用 mode=16（原地跳远）跳 5 次
第二关：sec002_seek() 函数根据鱼眼相机的橙色球掩膜比例（left_ratio_hit/right_ratio_hit > 0.019~0.02）触发撞击，循环搜索 4 个球
第三关：run_pid_align("ground", 526, vx=0.2) 用扫地相机 PID 寻线，526 轮 × 25Hz
第四关：change_gait() 上传低姿态自定义步态（low_gait），用 mode=62, gait_id=110 低姿通过三个通道
第五关：简化版方向校正后跳一次（鱼眼掩膜跳跃逻辑已注释）

change_gait() 方法读取 TOML 步态文件，转换为 LCM 命令并通过 user_gait_file channel 上传。

test_demo.py — 测试主控
与 master.py 结构类似，包含 masterNode_test 类，用于第五关回环路测试。mode_pub_callback 会发布 master_mode_topic（master.py 中该发布被注释了）。sec002_seek() 有更大的撞击阈值（0.0362 vs 0.019）和不同的避障策略。Robot_Ctrl_Node 在此继承自 Node。

test3.py — 第三关 PID 独立测试工具
多模式测试工具，支持 5 种运行模式：

模式	                参数	用途
默认（trackbar）	无	OpenCV 滑块实时调 Kp/Ki/Kd，4 种 gap 输入（手动/阶跃/正弦/随机游走）
--step	              阶跃响应	自动注入 ±80px 阶跃，分析超调量、上升时间、稳态时间
--sine	              正弦跟踪	振幅 120px、周期 5s 的正弦波，观察 PID 平滑跟随能力
--compare	      对比测试	同一输入下对比 PID vs Bang-Bang（±0.26）输出
--live	              实机控制	连接 ROS + LCM，订阅真实 ground_topic，按 s 开始/停止寻线
包含 PIDController、BangBangController、Telemetry（最大 400 帧历史）、TuningWindow（6 个 trackbar）、StepResponseAnalyzer 和 LiveRobotCtrl。

3. 视觉感知节点
adjust_node.py — 前向相机边线检测
订阅 /rgb_camera/image_raw
截取图像下 1/3 区域（ROI），转 HSV，用黄色阈值 [30,30,30]~[90,255,255] 分割赛道线
过滤面积 < 2000 的轮廓，找最优双边界对（间距 200~400px，接近 300px 理想值）
计算 gap = image_center - lane_center，7 帧滑动窗口平均
25Hz 发布 "edge_num gap" 到 adjust_topic
包含去噪锐化函数 denoise_and_sharpen() 和鱼眼畸变模拟函数 apply_fisheye_distortion_fast()
OpenCV 可视化：显示 ROI 框、轮廓重心竖线（蓝）、图像中心线（白）、道路中心线（红）、gap 水平指示条

ground_node.py — 扫地相机边线检测
订阅 /rgb_camera/image_ground
与 adjust_node 相同的处理流程（黄线 HSV 分割、轮廓检测、双边界对匹配、滑动窗口平滑）
关键差异：使用完整图像（不裁剪），双线间距判据为 500~1100px（而非 200~400px），因为扫地相机离地面更近
25Hz 发布 "edge_num gap" 到 ground_topic

fisheyes_adjust_node.py — 双鱼眼相机球/线识别
同时订阅 /image_left 和 /image_right
定义相机内参矩阵 K 和畸变系数 D 用于鱼眼去畸变（实际未调用）
图像裁剪：左图保留右 5/9，右图保留左 5/9，线检测用下 1/4
三类 HSV 掩膜同时计算：

掩膜	            阈值	             输出话题	            用途
宽球体	  [10,130,80]~[180,210,160]     fish_rgap_topic	 计算 rgap = left_ratio*0.9 - right_ratio，用于方向纠偏
窄橙色球   [10,130,80]~[100,210,160]	hit_ratio_topic	 面积占比 > 阈值触发撞击
黄色边线   [30,30,30]~[90,255,255]	fish_line_topic	 道路边界掩膜占比，用于跳跃判定（已注释）
过滤面积 < 2200 的轮廓，取最大轮廓计算面积占比。

seek_001_node.py — 前向橙色球识别
订阅 /rgb_camera/image_raw
橙色 HSV 阈值 [10,130,80]~[100,210,160]
取最大轮廓，计算面积占比 ratio 和水平偏差 dist
25Hz 发布 "ratio dist" 到 seek_001_topic
当前主要用于第一关前的橙色球搜索辅助，第二关主力是 fisheyes_adjust_node

4. 通信接口
robot_control_cmd_lcmt.py
LCM 控制命令结构体（自动生成），包含 mode、gait_id、contact、life_count、vel_des[3]、rpy_des[3]、pos_des[3]、acc_des[6]、ctrl_point[3]、foot_pose[6]、step_height[2]、value、duration 字段。通过 UDP udpm://239.255.76.67:7671 组播发送。

robot_control_response_lcmt.py
LCM 控制反馈结构体，包含 mode、gait_id、contact、order_process_bar（≥95 认为完成）、switch_status、ori_error、footpos_error、motor_error[12]。通过 udpm://239.255.76.67:7670 接收。

file_send_lcmt.py
LCM 文件传输结构体，仅含 data 字符串字段。用于上传自定义步态定义（*_Def.toml）和参数（*_full.toml）。

motion_interface.py
动作接口元数据库，定义 25 个预设动作的元数据（编号、名称、mode/gait_id、允许切换列表、参数范围、备注），包括：急停(0)、站立(111)、姿态展示(201)、趴下(101/102)、慢走(303)、小跑(305)、快走(308)、四腿跳跑(301)、牵绳遛狗(125)、原地跳远(132)、旋转左跳(130)、原地跳起(136)、握左右手(141/142)、坐下(143)、扭屁股(144)、芭蕾舞(151)、太空步(152)、俯卧撑(174)等。提供 get_action_info() 和 validate_params() 方法。

test.py
测试用文件（未读取，但应该是通信测试脚本）。

LCM 类型定义
robot_control_cmd_lcmt.lcm 和 robot_control_response_lcmt.lcm 是 LCM IDL 定义文件。

源代码
mqtt.c
MQTT-C 客户端库（Liam Bindle 开源实现，MIT 协议）。完整实现 MQTT 3.1.1 协议：mqtt_connect()（连接）、mqtt_publish()（发布，支持 QoS 0/1/2）、mqtt_subscribe()（订阅）、mqtt_unsubscribe()（取消订阅）、mqtt_disconnect()（断开）、mqtt_ping()（心跳）、mqtt_sync()（同步收发）、mqtt_reconnect()（重连）。内部使用消息队列管理待发送/待确认消息，提供 keep-alive 机制。

mqtt_pal.c
MQTT 平台抽象层。多平台兼容的 socket 收发实现，支持：Unix/Linux（BSD socket / send/recv，处理 EAGAIN）、mbedTLS、WolfSSL、BearSSL、OpenSSL BIO、Windows（Winsock）。提供 mqtt_pal_sendall() 和 mqtt_pal_recvall() 的跨平台实现。

cyberdog_log.cpp
日志工厂类，使用 ROS 2 rclcpp::Logger，提供单例 CyberdogLoggerFactory::Get_Logger() 方法。

cyberdog_parameter.cpp
参数解析器，支持 TOML 和动态库（.so）两种格式。通过 Python C API 调用 Python 模块获取配置数据，使用 toml11 库解析。提供 GetString/GetDouble/GetInt/GetBool/SetXXX 等方法进行类型安全的配置读写，支持嵌套键（点号分隔）和数组表查询。

cyberdog_fds_impl.cpp
文件描述符相关实现

cyberdog_json_test.cpp
JSON 功能测试

ROS 2 包构建配置。mqttc 是 C 库，cyberdog_common、cyberdog_machine、cyberdog_system 等是 C++ ROS 2 包。

总结
两个项目共同构成了湖北工业大学参加 2026 年小米杯 Cyberdog 比赛的完整技术方案：

维度	                     内容
比赛策略	五关串联：跳跃过障 → 鱼眼寻球撞击 → PID 视觉寻线 → 低姿步态通过 → 跳跃结束
感知系统	3 类相机（前向 RGB、左右鱼眼、扫地）+ HSV 颜色阈值分割 + 滑动窗口平滑
控制系统	PID 控制器（偏航 + 横移）+ LCM UDP 组播协议 + 10Hz 心跳维持 + 自定义步态上传
软件架构	ROS 2 Galactic + Python + OpenCV + C++ 工具库 + MQTT 通信
测试能力	独立 PID 调参工具（5 种模式）、离线模拟、实机控制切换、阶跃/正弦分析
基础设施	MQTT-C 客户端、TOML 参数系统、日志工厂、状态机、动作元数据库、多平台 socket 抽象
